# AetherTTS 整体架构蓝图（10M–15M 单步流式路线）

## 1. 设计原则与核心取舍

面向 **嵌入式 Linux（中低端手机 SoC 级别、纯 CPU）** 的 Siri / 小爱同学级语音助手，本架构围绕四个铁律展开：

1. **单步直出（1-NFE），消灭多步迭代乘数**：放弃扩散/多步 Flow Matching，沿用 **Kokoro / StyleTTS2 精简推理范式**，推理期一次前向直接输出波形。
2. **显式韵律解耦（Duration + F0 + Energy）**：保证 100% 不吞字、不乱读、零幻觉，同时允许端侧实时调节语速与停顿。
3. **重训练、极轻推理 + 单音色极致特化**：把复杂的大语音模型判别器（WavLM SLM Discriminator）、多尺度频谱判别器（MSD/MRD）以及教师特征监督全部留在训练期；因**只需要 1 个音色**，推理期彻底移除 Speaker Embedding、风格编码器和 AdaIN 多说话人条件分支（同 Paradee 单音色特化思路），模型 100% 容量服务于这 1 个声音，进一步省掉算力与参数。
4. **全程因果 / 有限右前瞻（Finite Right Lookahead）**：从文本前端、韵律预测到声码器，所有层均严格约束右前瞻窗口与左状态缓存，做到**流式输入（对接 LLM）+ 流式输出（帧级吐出 PCM）**数学等价、零拼接爆音。

## 2. 端到端数据流与参数/算力预算

借鉴 Kokoro-82M 与 Paradee-8M（2026）的算力剖析结论——**原版 Kokoro-82M 有 2/3 参数和 92% 的计算量都耗在 53M 的 ISTFTNet 解码器上**——AetherTTS 在单音色特化下可把总参数进一步压到 **8M–12M**，且单卡 1 天内即可完成收敛：

```text
LLM Token 流 ("帮我查一下明天的 Weather 怎么样？")
       │
       ▼
┌──────────────────────────────────────────────────────────┐
│ 1. 流式文本前端 (Streaming Text Frontend)                │
│    • 流式 TN (数字/时间/符号，带 2~4 字右前瞻缓存)        │
│    • 词典 + 轻量多音字消歧/韵律边界预测 (~1.5M, INT8)     │
│    • 统一中英音素表 (声母/韵母+声调 + ARPAbet重音 + LangID)│
└───────────────────────────┬──────────────────────────────┘
                            │ 音素流 + 韵律/语种标记 (每步延迟 L_txt tokens)
                            ▼
┌──────────────────────────────────────────────────────────┐
│ 2. 流式文本编码与韵律预测侧 (Text & Prosody Side, ~4.0M)  │
│    • Streaming Backbone (待实验定型: SWA / Mamba / RWKV) │
│      输入: 音素序列，支持 O(1)/O(W) 左状态 + L 步右前瞻   │
│    • Duration Predictor (预测每音素帧数, 100 Hz / 80 Hz)  │
│    • 帧级扩展 (Length Regulator, 按音素流式逐块扩展)      │
│    • F0 (基频) & Energy 预测器 (因果/微前瞻轻量卷积)      │
└───────────────────────────┬──────────────────────────────┘
                            │ 隐状态 h_frame + F0 + Energy (按 160~240 ms 块流出)
                            ▼
┌──────────────────────────────────────────────────────────┐
│ 3. 瘦身因果频域解码器 (Causal Decoder/Vocoder, ~3.5M)    │
│    • 方案 3a: 瘦身 Causal Source-Filter iSTFTNet (24 kHz) │
│    • 方案 3b: 轻量 Causal Vocos-Lite (ConvNeXt + iSTFT)  │
│    • 维护严格卷积 Ring-Buffer 状态 + iSTFT Overlap-Add    │
└───────────────────────────┬──────────────────────────────┘
                            │ 24 kHz 16-bit PCM 流 (Zero-Click 无感拼接)
                            ▼
                 嵌入式 Linux ALSA / 音频播放缓冲
```

### 参数量与嵌入式 CPU 算力预算表（单音色特化，24 kHz，Hop = 240 / 300 采样点）

| 模块 | 参数预算 | INT8 / 混合精度体积 | FLOPs 占比（估算） | 精度策略 |
| :--- | :--- | :--- | :--- | :--- |
| 流式多音字 + 韵律前端 | ~1.5M | ~1.6 MB | < 2% | INT8 |
| 文本编码 + 韵律/时长/F0 预测 | ~4.0M – 5.0M | ~4.5 – 5.5 MB | ~15% | INT8 / FP16 |
| 因果 iSTFTNet / Vocos-Lite 解码器 | ~3.0M – 4.5M | ~4.5 – 6.5 MB | ~83% | 主体 INT8/FP16，**输出层与 iSTFT 保持 FP16/FP32** |
| **端到端总计（单音色）** | **~8.5M – 11.0M** | **~10.5 – 13.5 MB** | **100%** | 嵌入式 RAM 峰值 < 50–80 MB |

> **关键经验（来自 Paradee-8M 消融结论）**：
> - 解码器内部通道数从 Kokoro 的 `1024 / 512` 裁剪到 `256 / 128`（~3.9M 参数）后，每秒音频计算量可压到 **~3.4 GFLOPs/s**（较原版 Kokoro 降 15×），在双核 Cortex-A76 上可轻松跑到 **RTF 0.04–0.08**。
> - 小模型（~10M）几乎没有冗余通道，**权重 INT8 基本无损**，但不可强行压到 INT4（声码器底噪与机械感会显著恶化）。

> **实现层修订（`a5` 唯一主力 `E3` 定型与闭环升级，2026-11）**
> - **唯一主力主干定型（`ChunkLookaheadBackbone`, `C=4, L=8, W=48`）**：正式锁定 `E3_chunk_attn_C4_L8` 为唯一默认路线（其余 `E0/E1/E2/E4` 对照类归档保留）。KV Cache 存储**未旋转 K** 并在固定 `[0 .. W+M)` 局部窗口施加相对 RoPE，使多句连续数小时不重置状态依然严格 $O(1)$、零位置外推与零表重分配；训练期走层主序 `unfold + SDPA` 零循环全并行。
> - **浊音感知 `F0 + UV` + 2D 共振峰结构损失 + 时长梯度隔离**：单头联合预测 `(f0, uv_logit)`，仅在浊音帧监督 F0 并自动将清音帧基频嵌入置零；引入频率轴共振峰差分 + 时间轴瞬态差分结构损失抑制纯 L1 模糊；对 `dur_predictor` 输入做 `0.1x` Stop-Gradient 缩放。
> - **声学 → 声码器 GTA 闭环 + 帧率谐波源 `CausalVocosLite`（`a5`）**：管线改为先训声学模型、导出逐样本帧对齐的 GTA 预测谱，再在声码器 Stage 2 混入 50% GTA Mel 闭环精调；声码器内置 `mel_mean/mel_std` 归一化、`CausalHarmonicSource`（`float64` $\phi_0 \bmod 1$ 包裹基频积分 + 12 阶谐波正余弦注入），配合修复转置后的 `(B, 1, T, F)` 幂律压缩 `SpecDisc`（73-bin 谐波感受野）与 `PeriodDisc[2, 3, 5, 7, 11]`，根治稳态元音相位漂移电音。
> - **动态双档低延迟流式调度**：声码器首包仅需攒够 `6` 帧（64 ms）即刻解码吐出首段 PCM，稳态自动切回 `16` 帧（171 ms）高吞吐块，且波形与离线整句前向误差 `< 1e-5`。

## 3. 中英双语与混读统一音素设计（`v3` 音系完备版）

为了避免“中文切英文时口音割裂、儿化句丢停顿或词间 `<sp>` 抢占辅音帧”，中英文进入**同一套共享 Embedding 空间**，附加 **Language ID Embedding**（`PUNC/SPEC=0, ZH=1, EN=2`）与 **Boundary ID Embedding**（`0`: 音节/词内，`1`: 词内音节首，`2`: 词/韵律词 `#1-#3`/语种切换首）：

1. **中文音素集合**：
   - 严格区分齐齿呼 `i`、舌尖前元音 `ii`（`zi/ci/si`）与舌尖后元音 `iii`（`zhi/chi/shi/ri`），完整还原 `y/w` 零声母与 `ian/iou/uei/uen/ve` 省写韵母，覆盖全部 **20,901 个 CJK 汉字零 `<unk>`**。
   - 显式建模儿化韵尾 `zh_er_coda`、“一 / 不 / 叠字”变调与双音节韵律步三声变调；逐字符对齐标贝儿化句标点与 `#1–#3` 韵律边界。
2. **英文音素集合**：
   - 采用 **CMUdict ARPAbet（带 0/1/2 重音标记，共 69 音素）**，未登录词由 `g2p_en` + 字母级回退兜底。
   - **中英连读零伪停顿**：移除强制占帧（`dur >= 1`）的词间 `<sp>` 静音符，改由首音素 `boundary_id = 2` 表征词界与语种切换，彻底避免连读短辅音被吞帧。
3. **总词表大小**：共 **293 个 Token**，词表精炼、收敛极快。

## 4. 解码器（声码器）路线细化：Causal iSTFTNet vs Causal Vocos-Lite

实验阶段将在解码器侧做两组小规模对比，两者共同点是**均以 iSTFT 替代昂贵的高倍率时域转置卷积**：

| 对比维度 | 候选 1：瘦身 Causal Source-Filter iSTFTNet（Kokoro/Paradee 系） | 候选 2：Causal Vocos-Lite（ConvNeXt + iSTFT） |
| :--- | :--- | :--- |
| **物理先验** | 显式正弦谐波激励（Hn-NSF）+ 轻度上采样（如 5×/6×）+ iSTFT | 无显式谐波源，全程在帧率上跑因果 ConvNeXt，直接预测复数谱 + iSTFT |
| **F0 跟随度** | **极高**，中文四声和轻重音曲线极其贴合预测 F0，小参数不易发虚 | 依赖网络隐式合成谐波，极小参数下偶有轻微相位模糊 |
| **ARM CPU 速度** | 很快（需将上采样后的通道数压到 64–128） | **极快**（全程低帧率 1D 深度可分离卷积，最适配 ARM NEON） |
| **小模型常见隐患** | 纯频谱训练容易在 2–8 kHz 出现轻微“嗡嗡声”（需调高对抗损失权重 + 训练无关相位锁定滤波解决） | 高频气声需靠多尺度 STFT + MPD/MRD 对抗训练拉起 |

## 5. 训练策略与损失函数规划（严控训练时长，单卡 1 天内收敛）

采用**单音色 20–25 小时直接训练 + 分阶段引入对抗损失**（不再做数百小时多说话人预训练，避免训练时长失控与容量稀释）：

1. **Stage 1：声学对齐与频谱重建热身（~50k–80k steps，约 3–6 小时）**
   - 直接在严控的 **20–25 小时单音色双语黄金集** 上，使用 MFA 强制对齐时长 + RMVPE/Harvest 基频 F0 + 对数能量，以 L1/Huber + 多分辨率 STFT 损失让文本编码器、Duration/F0/Energy 预测器与解码器快速稳定收敛。
2. **Stage 2：对抗精调（唤醒真人质感，~50k–100k steps，约 6–12 小时）**
   - 引入 **MPD（Multi-Period Discriminator）+ MRD（Multi-Resolution STFT Discriminator）+ 冻结的 WavLM-Base SLM 对抗判别器**（借鉴 StyleTTS2）。
   - **关键超参经验**：适当降低梅尔/频谱 L1 权重（如从 `45` 降至 `3–10`），避免频谱损失压死对抗梯度导致电子味/嗡嗡声，让判别器充分塑形 2–8 kHz 自然气声与谐波纹理。
3. **可选加速（Paradee 白盒半拆蒸馏）**：
   - 如发现 8M–10M 流式小模型在有限右前瞻下韵律弱于全句模型，可先在同份 20–25h 数据上训一个 ~30M 非流式全双向教师，再对流式小模型做特征/时长/F0 白盒蒸馏（详见 [`03_teacher_distillation_pipeline.md`](03_teacher_distillation_pipeline.md)）。
   - 完整质量验收门禁见 [`04_evaluation_protocol.md`](04_evaluation_protocol.md)。

## 6. 端到端首包延迟预算（嵌入式 Linux 纯 CPU 目标）

假设 LLM 首包吐出速度约 20–30 token/s，TTS 自身配置为 `右前瞻 L = 3 字`、`音频输出块 C = 160 ms`：

| 阶段 | 估算耗时 | 说明 |
| :--- | :--- | :--- |
| 流式前端（TN + 多音字 + 韵律） | `< 5 ms` | 轻量词典 + INT8 小模型 |
| 流式文本编码 + Duration/F0 首块 | `15 – 35 ms` | 仅计算增量新音素，复用左状态 |
| 因果声码器首块（160 ms 音频） | `20 – 45 ms` | 双核 ARM Cortex-A76，约 3.5 GFLOPs/s |
| ALSA 低延迟环形缓冲写入 | `20 – 40 ms` | 2–3 个 period 缓冲 |
| **TTS 自身首包延迟（TTFA）** | **`60 – 125 ms`** | 不含 LLM 吐出前 `C_init + L` 字的等待时间 |
