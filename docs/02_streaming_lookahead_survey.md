# 流式输入与有限右前瞻（Right Lookahead）技术调研

## 1. 为什么中文/中英混读流式 TTS 必须具备「有限右前瞻」？

如果流式输入主干是**严格因果（0 前瞻，只能看历史不能看未来）**，在中文和英文语音合成中会出现几个无法靠调参消除的结构性硬伤：

| 语言现象 | 举例 | 为什么 0 前瞻会翻车？ | 所需最小右前瞻 |
| :--- | :--- | :--- | :--- |
| **中文多音字消歧** | 「行」→「银行(`háng`)」vs「行走(`xíng`)」；「长」→「行长(`zhǎng`)」vs「长短(`cháng`)」 | 读到「行」或「长」时不知道后面跟着什么字 | **2–4 个汉字** |
| **中文三声变调** | 「你好(`ní hǎo`)」「展览馆(`zhán lán guǎn`)」 | 第一个三声是否变成二声取决于紧随其后的声调与词边界 | **2–3 个汉字** |
| **文本正则化（TN）边界** | LLM 刚吐出 `20`，后面可能是 `2026年`、`20%` 或 `20块钱` | 还没看到数字结束符/单位，无法确定读作「二零二六」还是「二十」 | **2–4 个字符**（或到非数字字符） |
| **中文韵律停顿与语调** | 问句句末上扬、长短句词组切分、中英混读边界停顿 | 当前字的时长与基频斜率受后续 1 个韵律词影响 | **3–5 个音素/2–4 字** |
| **英文重音与连读** | 复合词重音、`a / an`、辅音连读 | 音素时长受词内及紧邻下词音节影响 | **1 个英文词（~4–6 音素）** |

### 核心结论：有限右前瞻（Finite Right Lookahead）的“甜点区间”
* **文本/音素侧右前瞻 $L_{\text{txt}}$**：控制在 **2–4 个汉字（或 1 个短词，约 4–8 个音素）**，即可解决 95%+ 的多音字、三声变调与短语韵律问题。
* **帧级声学/声码器侧右前瞻 $L_{\text{frame}}$**：控制在 **2–4 帧（20–40 ms）**，足够保证基频平滑与辅音过渡清晰，且几乎不增加感知延迟。
* **算法延迟公式**：
  $$\text{TTFA}_{\text{total}} = T_{\text{LLM}}(N_{\text{first}} + L_{\text{txt}}) + T_{\text{front}} + T_{\text{acoustic}}(C_{\text{first}}) + T_{\text{vocoder}}(C_{\text{first}} + L_{\text{frame}}) + T_{\text{audio\_buf}}$$
  其中 $N_{\text{first}}$ 是首块发射的最小字数（如 2–4 字），$L_{\text{txt}}$ 是右前瞻字数（如 2–4 字），$C_{\text{first}}$ 是首块合成的音频时长（如 160 ms）。只要 LLM 吐出前 **5–8 个字**，系统就能立刻发射第一批带完整右前瞻的音素并发出第一声。

## 2. 四类流式输入主干深度对比（实验阶段候选）

在单步非自回归架构（魔改 Kokoro）中，**流式主干主要位于“音素编码器 + 韵律/时长/F0 预测器”这一侧（总参数约 4M–6M）**。

> 核心问题：**如何同时拥有「长距离左历史上下文」+「精确 $L$ 步右前瞻」+「训练并行与流式推理数学 100% 一致」+「嵌入式 ARM CPU 高效运行」？**

下面对比调研阶段锁定、将在实验阶段逐一实测的四类主干：

### 候选 1：滑动窗口因果注意力（Sliding Window Attention, SWA）+ 前瞻卷积 / Chunk-Zipformer-Lite

* **工作原理**：
  * 每个位置 $t$ 的 Attention Mask 严格限定在 $[t - W,\; t + L]$ 范围内（向左看 $W$ 步有界历史，向右看 $L$ 步有限前瞻）。
  * 配合 **Depthwise Separable Conv（或 ConvNeXt 块）** 捕捉局部邻域发音协同（Co-articulation）。
  * 推理时按 Chunk（如每来 2–4 个新音素）增量计算，维护固定长度 $W$ 的 **Ring-Buffer KV Cache**，显存与单步算力均为严格常数 $O(W)$，不随对话长度增长。
* **右前瞻实现方式**：**最原生、最干净**。
  * **Chunk-wise Mask（块级前瞻）**：类似 WeNet / Streaming Zipformer，每个 chunk 内的 token 互相可见，外加看下一个 chunk 的前 $L$ 个 token（注意：若直接跨层叠加 $K$ 层核宽为 $k$ 的双向卷积，总右前瞻会线性膨胀为 $K \cdot \lfloor k/2 \rfloor$！因此必须**只在首层做一次 $L$ 步右前瞻，或在深层采用严格因果卷积 + Attention 统一共享同一个 $L$ 步右前瞻窗口**）。
* **嵌入式 ARM CPU 适配性**：**★★★★★（最成熟）**
  * 全部由标准 `MatMul`、`Softmax`、`Conv1d`、`LayerNorm` 组成，ONNX Runtime / MNN / NCNN 原生 ARM NEON & INT8 加速最成熟。
  * 在文本侧序列很短（$W = 32\text{–}64$ 音素）的情况下，Attention 矩阵极小，算力开销微乎其微。
* **潜在缺点**：
  * 超过左窗口 $W$ 的长距上下文（如一整段 200 字长回复开头确立的说话语境/语速）会被截断。

---

### 候选 2：Mamba / Mamba-2（Selective State Space Model, SSM）+ 有限右前瞻

* **工作原理**：
  * 核心递推 $h_t = \bar{A}_t h_{t-1} + \bar{B}_t x_t,\; y_t = C_t h_t$，将**无限长度左历史**压缩进固定大小的隐状态矩阵 $h_t$（严格 $O(1)$ 状态内存），且 $\Delta_t, B_t, C_t$ 由当前输入动态门控，具备类似注意力的内容选择能力。
  * 已有 2025–2026 年语音工作（如 Samsung SMAM 等）证明 20M 级 Mamba 在 CPU 流式 TTS 上可实现极低首包延迟。
* **如何补齐「右前瞻能力」**？（关键设计！）
  SSM 本身是严格单向因果的，要给它加上 $L$ 步右前瞻，有三种典型设计（实验阶段重点测试方案 A/B）：
  1. **Delayed Emission（前瞻延迟发射，最简洁）**：输入序列向前多喂 $L$ 个 token 到位置 $t + L$，但把位置 $t + L$ 的输出对齐监督到位置 $t$ 的目标（Duration/F0/特征）。这样所有层自动共享精确的 $L$ 步右前瞻，**无额外模块、状态完全复用**，只需把输入与目标错位 $L$ 步训练！
     > ⚠️ 注意：Delayed Emission 需确保第 $t$ 个音素自身的 embedding 通过残差/对齐索引显式注入到 $t+L$ 处，否则模型很难精准记住“$L$ 步前那个音素具体是谁”。
  2. **前置有限前瞻编码 + 因果 SSM（Hybrid Front-Lookahead）**：最底层放 1 层带 $L$ 步右前瞻的局部卷积 / 局部注意力融合 $[t-k, t+L]$ 信息，再送入多层严格因果 Mamba 压缩无限左历史。
  3. **Chunk 级局部双向小窗口 + 全局因果 SSM**：块内少量未来信息由轻量局部注意力聚合，块间靠 SSM 状态传递。
* **嵌入式 ARM CPU 适配性**：**★★★☆☆（需特别注意导出方式）**
  * **训练期**依赖 `mamba-ssm` 的 CUDA `selective_scan` 并行内核；但**嵌入式 CPU 推理期不能用该 CUDA 算子**。
  * **解法**：推理导出时，必须切换为**显式循环单步/小块递推图（Stateful Step Graph）**——在单步递推模式下，Mamba 的核心计算只是 `Conv1d(k=4)` + 若干 `Linear` + `Exp` + 逐元素乘加，**完全不依赖特殊 CUDA 算子**，可以导出为纯标准 ONNX / MNN 或手写极简 C++ ARM NEON 循环。
  * 需要注意的是，Mamba 的隐状态维度 `d_inner × d_state` 的逐元素读写对 CPU Cache 局部性较敏感，实验阶段需实测其与 SWA/RWKV 在 ARM 上的真实耗时对比。

---

### 候选 3：RWKV（v6 / v7 风格线性注意力 / WKV 状态机）+ 有限右前瞻

* **工作原理**：
  * 同样是 **$O(1)$ 恒定左状态内存** 的线性复杂度循环架构（Time-Mixing 维护衰减键值累积矩阵 $S_t = \text{diag}(w_t) S_{t-1} + k_t^\top v_t$，Channel-Mixing 做门控 FFN）。
  * RWKV-v6/v7 引入了数据依赖衰减（Data-Dependent Decay）和状态擦除/更新（Delta Rule），在短中长度序列建模上已非常逼近 Transformer。
* **如何补齐「右前瞻能力」**？
  * RWKV 原生的 `TokenShift` 本质上就是把当前步 $x_t$ 和上一步 $x_{t-1}$ 做线性插值；将其扩展为**因果 + 有限前瞻 Shift / 1D 卷积**（例如在底层融合 $x_{t-1}, x_t, x_{t+1}, \dots, x_{t+L}$），或同样采用 **前置 $L$ 步局部前瞻层 + 多层因果 WKV**，非常自然且不会引起跨层感受野失控。
* **嵌入式 ARM CPU 适配性**：**★★★★☆（比 Mamba 更友好）**
  * WKV 的单步递推全是标准的矩阵向量乘（GEMV）和逐元素乘加，在 `rwkv.cpp` / `ggml` / `ONNX Runtime` / `MNN` 生态里早有极成熟的纯 CPU 端侧落地验证，非常适合嵌入式 Linux。

---

### 候选 4（必做对照组）：Causal ConvNeXt + Uni-GRU + 前瞻卷积（轻量传统基线）

* **为什么实验阶段一定要带上它？**
  * 在 **4M–6M 参数**、**音素级序列（典型句子 15–80 音素）** 这个尺度下，**简单的 1 层 $L$-Lookahead 卷积 + 因果 ConvNeXt + 1–2 层单向 GRU** 往往出人意料地强，且在 ARM CPU 上速度极快、零导出坑。
  * 只有把它设为严格 Baseline，我们才能在实验阶段客观回答：**“引入 SWA / Mamba / RWKV 到底带来了多大的韵律/长句收益？值不值得多付那一点算力或工程复杂度？”**

### 候选 5：门控 DeltaNet（短因果卷积 + 线性注意力 + Delta Rule 写入 + 状态门控）

* **工作原理**：逐头维护状态矩阵 $S_t \in \mathbb{R}^{K\times V}$，在 Q/K/V 经过 4-tap 因果短卷积 + SiLU 与 L2 归一化（$\hat q,\hat k$）后，输出 $o_t = S_t^\top \hat q_t$，$O(1)$ 状态、$O(T)$ 计算的线性注意力。
  * **标准 Gated Delta Rule 写入**：$S_t = \alpha_t (I - \beta_t \hat k_t \hat k_t^\top) S_{t-1} + \beta_t \hat k_t v_t^\top = \alpha_t S_{t-1} + \beta_t \hat k_t (v_t - \alpha_t S_{t-1}^\top \hat k_t)^\top$。先按标量状态门控 $\alpha_t \in (0,1)$ 遗忘旧状态，再沿当前 key 方向擦除冗余分量并写入新值（$\beta_t \in (0,1)$），即使 $\alpha_t \to 0$ 完全重置历史仍能干净写入当前帧信息。
* **右前瞻**：与 E1/E2 相同，集中在底层 $L$ 步前瞻层，DeltaNet 及其内部短卷积自身严格因果。
* **训练并行**：块内用 WY 表示把 Delta Rule 写成单位下三角线性方程组（全程在 log 空间先 mask 后 `exp` 保证强遗忘下数值稳定，三角求逆用倍增全并行），块间只递推状态；推理逐步递推，二者数学等价。
* **嵌入式 ARM CPU 适配性**：与线性注意力同级，推理单步是若干小矩阵向量乘加逐元素运算（状态 $S_t$ 需保 FP32）。
* **定位**：Phase 1 中作为 **$O(1)$ 状态族唯一代表（`E4_gated_deltanet_L8`）**，取代冗余的 SSM 与累加式 WKV，验证长段落无限流式状态机值不值得替代有界 KV。

---

### 候选 6：分块深层双向流式注意力（Chunk-wise Deep Lookahead Attention，Phase 1 主力冲冠）

* **工作原理**：每次流式推进以「提交块 $C=4$ 音素（≈ 2 汉字）+ 前瞻块 $L=8$ 音素（≈ 4 汉字）」为活动窗口，**全部 5 层**同时因果读取长度 $\le W$（48 音素）的已提交 KV Cache，并在 $[C+L]$ 内部做完整多层双向自注意力 + 局部因果 ConvNeXt。
* **零前瞻膨胀的本质**：每一层算完后，**只把前 $C$ 个已提交 token 的 KV 与卷积状态写入缓存，彻底丢弃后 $L$ 个前瞻 token 的状态**（下一块到来时重算这几个前瞻 token）。因此即使堆叠 5 层甚至 12 层，全局右前瞻也严格锁死在 $L$，绝不叠加膨胀。
* **为何最契合 LLM 流式输入**：
  1. **多层深交互看未来**：打破「仅第 1 层浅层 Conv 看右边、上层全盲」的天花板，5 层均可围绕未来 3–4 个汉字做词组停顿、变调与重音规划；
  2. **原生适配流式前端暂定纠错**：提供 `forward_committed_with_lookahead(x_commit, x_lookahead, state)` 接口——前端滑窗里暂定的多音字/数字/英文残词即使下一拍被修正，也从未写入历史状态；
  3. **音素率算力代价极低**：音素率仅 ~10 Hz，重算 8 个前瞻音素在双核 ARM CPU 上耗时 `< 0.5 ms`。

## 3. 流式输入主干核心特性速查表（Phase 1 裁决）

> **Phase 1 矩阵裁决（2026-11 `a4`）**：在 15–80 音素短句 + 纯 CPU 端侧场景下，右前瞻机制与长度对自然度的影响远大于“在多种左历史线性压缩算子间横评”。因此砍掉冗余的 **Mamba/SSM** 与 **累加式 WKV** 两个槽位，保留 **标准门控 DeltaNet** 作为 $O(1)$ 状态族独苗，将省出的算力聚焦到 **`L=0` vs `L=8` 拐点消融** 与 **5 层深双向分块前瞻 `ChunkLookaheadBackbone`**。

## 4. 关键工程陷阱：多层的「右前瞻膨胀（Lookahead Explosion）」

在设计多层流式 TTS 网络时，**最容易踩的坑就是右前瞻叠加爆炸**：

> 假设有 5 层网络，每层都直接把右看 $L$ 个 token 后的隐状态缓存供上层读取，那么第 5 层的有效右前瞻会膨胀成 $5 \times L$！首包延迟直接失控。

### 规避规范（AetherTTS 强制约束 + 自动化扰动硬门禁）
1. **全局右前瞻预算严格锁死**：文本侧 $L_{\text{txt}} = 8$ 音素（≈ 4 汉字，与 Phase 2 流式前端消歧滑窗共享），帧级 `frame_decoder[0]` $L_{\text{frame}} = 2$ 帧（21 ms），声码器 `embed` $L_{\text{voc}} = 2$ 帧（21 ms）。
2. **两条零膨胀合法路线（Phase 1 直接 PK）**：
   - **路线 A（浅层集中前瞻：`E1 / E2 / E4`）**：只有第 1 层 `CentralizedLookaheadBlock` 看右边 $L$ 步，第 2–6 层严格因果。
   - **路线 B（分块深层前瞻：`E3 ChunkLookaheadBackbone`）**：全部 5 层在 `[C + L]` 内做深双向交互，但每层缓存严格只提交前 `C` 步、丢弃后 `L` 步，从数学上杜绝跨层前瞻叠加。
3. **强制扰动单测门禁**：训练前自动改写 `index >= c_probe + L` 的全部未来音素，断言所有已提交位置 `[:c_probe]` 的隐状态变化严格等于 **`0.0`**，并校验批训练右填充等价与逐块流式↔离线最大绝对误差 `< 1e-4`。

在 **单人高质量语料**（中文 `BZNSYP` / 英文 `LJSpeech`）上跑完以下 6 槽严格控制变量矩阵，**锁定唯一主干定型**：

### 固定控制变量
* **推理参数规模**：声学侧 ~4.9M–5.8M，叠加 `CausalVocosLite`（~3.67M）端到端总计 ~8.6M–9.5M
* **统一帧级与声码器配置**：24 维音素内多尺度相位特征 + `frame_decoder[0]` 集中式 2 帧右前瞻 + `CausalVocosLite` 集中式 2 帧右前瞻与 `n_fft // 2` OLA 对齐

| `E1_conv_unigru_L8` | Causal ConvNeXt + Uni-GRU | $O(1)$ | 1 层浅前瞻 `L=8` 音素 | 极简端侧基线 + 对比 `L=0` 量化 4 字前瞻净收益 |
| `E2_swa_L8` | SWA + Causal ConvNeXt | $W = 48$ | 1 层浅前瞻 `L=8` 音素 | 与 `E3` 同前瞻同窗口的浅前瞻对照组 |
| **`E3_chunk_attn_C4_L8`** | **5 层深双向分块前瞻注意力** | **$W = 48$** | **5 层深双向 `C=4, L=8`（丢弃前瞻 KV）** | **主力冲冠**：深层双向看未来 4 字能否逼近 `E0` 天花板 |
| `E4_gated_deltanet_L8` | 标准门控 DeltaNet（含 4-tap 短卷积） | 无限 $O(1)$ | 1 层浅前瞻 `L=8` 音素 | $O(1)$ 状态族独苗：评估长段落无限流式收益与 CPU 代价 |

### 评测指标（定型决策依据）
1. **可懂度**：中文 CER / 英文 WER / 中英混读 MER（Whisper 自动评测）+ 多音字与三声变调专项。
2. **自然度与韵律**：UTMOS 客观分 + 人工盲听 ABX（重点听长句语调、三声变调、协同发音清晰度、中英切换）。
3. **流式硬门禁**：流式↔离线最大波形误差、零前瞻膨胀扰动检查（严格 `0.0`）、切块接缝爆音检测（`Seam_Click`）。
4. **CPU 推理性能**：2 线程纯 CPU 端到端 **RTF**、**TTFA 首包延迟**、INT8 权重体积。

## 6. Phase 1 实测裁决与 `a5` 唯一路线定型（2026-11）

首轮 6 槽控制变量实验（详见 [`05_phase1_a4_experiment_report.md`](05_phase1_a4_experiment_report.md)）证实：
* **`E3_chunk_attn_C4_L8` 全面夺冠**：在验证集 Mel L1（`0.5281`）、UTMOS、声纹一致性（`SIM=0.796`）上显著优于同前瞻浅层对照 `E2_swa_L8`（`0.5769`）、`E1_conv_unigru_L8`（`0.5460`）以及门控 DeltaNet `E4`（`0.6038`），同时 2 线程 CPU `RTF = 0.072 < 0.10`、流式接缝零爆音。
* **正式收敛为唯一默认路线（`a5`）**：
  1. 自 `a5` 版本起，`EXPERIMENTS` 默认仅保留 **`E3_chunk_attn_C4_L8`**（其余对照主干类保留在源码中归档备查，不再默认执行）；
  2. `ChunkLookaheadLayer` 升级为**缓存未旋转 K + 固定 `[0 .. W+M)` 局部窗口相对 RoPE**，彻底消除多句连续数小时不重置状态时的位置计数无限增长与大角度外推风险；
  3. 训练期采用 `unfold + SDPA` 层主序零循环全并行（并剪枝末层前瞻查询），兼具高速训练与 `~1e-6` 级流式数学等价。
