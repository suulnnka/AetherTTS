# AetherTTS 生成质量评测体系（单音色中英流式专版）

TTS 训练中最常见的坑是**只看训练 Loss**（Mel L1 降得很低但声音发闷发糊）或**只看单一自动打分**（如 UTMOS 在现代神经 TTS 上容易饱和甚至与对话自然度负相关）。

本评测体系专为 **单音色、中英双语+混读、有限右前瞻流式 TTS** 设计，分为 **4 维自动化客观指标（训练与实验期高频跑）** + **1 套极轻量 50 句人工盲听（关键决策拍板用）**。

---

## 一、四维自动化客观指标（门禁体系）

所有模型对比实验必须在**同一套固定评测集**上跑出以下四维指标，且始终以**参考真声 / 教师语音作为 Gold Anchor（上界锚点）**，不看孤立绝对值。

### 1. 发音可懂度（Intelligibility）—— 查吞字、错读、混读崩坏

| 指标 | 评测工具 | 适用子集 | 达标门禁（参考） | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **中文 CER** | `SenseVoice-Small` / `Paraformer-zh` | 纯中文常规 + 困难多音字 | `< 1.5%`（困难集 `< 5%`） | 比 Whisper 更懂中文普通话与常见多音字 |
| **英文 WER** | `Whisper-large-v3-turbo` | 纯英文常规 + 常用词 | `< 2.5%` | 抓吞音、重音错乱与长难词错读 |
| **中英混读 MER** | `SenseVoice` / `Whisper-large-v3` | 中英夹杂句（中文按字、英文按词） | `< 3.0%` | 重点检查英文词前后是否吞字或中文口音化严重 |
| **极短句稳定性** | 同上（单独切出 3–8 字极短句统计） | 首包极短句 | 与常规句差距 `< 1.0%` | 2026 多项基准证实：TTS 最容易在极短句上发虚或截断 |

> **为什么必须单列“极短句”？**
> 流式对话首包往往只有 4–8 个字，如果模型只在长句上好看、短句发飘，实际对接 LLM 时体验会非常差。

---

### 2. 自然度与声学伪影（Naturalness & Signal Artifacts）—— 查机械味、底噪、嗡嗡声

单看一个 MOS 预测模型极易被“干净但呆板”的声音骗过去，必须**互补组合 3 类打分**：

| 指标 / 工具 | 擅长抓什么问题 | 局限性（避坑提示） | 目标阈值 |
| :--- | :--- | :--- | :--- |
| **UTMOS / UTMOSv2** | 整体听感基线、明显音质劣化、声码器失真 | 在高质量对话/韵律细节上易饱和，不能单独作为最终排序依据 | 与 Gold Anchor 差距 `< 0.15`（约 `≥ 4.0–4.3`） |
| **DNSMOS (P.835 SIG / BAK / OVRL)** 或 **TorchAudio SQUIM** | 底噪、高频沙沙声、电流底噪、削波与失真 | 偏爱过度平滑的声音，对“朗读腔/无感情”不敏感 | `OVRL ≥ 3.3`，`BAK ≥ 3.8` |
| **NatScore**（基于 SpeechJudge-Data 99K 中英+混读人类偏好对训练，轻量可 CPU 跑）或 **TTSDS2** | **现代神经 TTS 的细微不自然**：韵律突兀、气口错位、中英切换违和感 | 属于相对排序指标，适合同测试集 A/B 对比 | 越高越好，与人类偏好排序最贴近 |
| **2–8 kHz 频谱与谐波检查（声码器专项）** | 瘦身 iSTFTNet/Vocos 常见的 2–8 kHz “谐波泄漏/机械嗡嗡声” | 需抽样观察语谱图与高频能量比 | 3–8 kHz 保持自然气声扩散，无死板平行谐波条纹 |

### 3. 单音色一致性与跨语种不串味（Speaker Consistency）

对「单音色中英双语」模型而言，最尴尬的翻车是：**说中文像小爱同学，切到英文单词突然变了一个人（或声线变粗/变细）**。

* **评测工具**：`WeSpeaker (ResNet221-LM)` 或 `CAM++ / ECAPA-TDNN` 声纹模型提取句级 Embedding 余弦相似度（**SIM**）。
* **必测 3 项**：
  1. **中文-参考声纹 SIM**：确认模型没跑偏音色（目标 `≥ 0.80`）。
  2. **跨语种 SIM（生成英文 vs 生成中文）**：衡量中英文是否真正“同一个人说”（目标 `≥ 0.72–0.78`，越接近越好）。
  3. **长句与跨句时间漂移（Temporal Drift）**：把 15–30 秒长句或多句连续流式输入切成首/中/尾三段分别测 SIM 和 UTMOS，验证流式状态（`ChunkLookaheadBackbone` 未旋转 KV + 局部窗口相对 RoPE 及谐波振荡器包裹相位）在超长连续输入下不会衰减、失真或音色飘移。

---

### 4. 流式与右前瞻专项指标（AetherTTS 核心护城河）

传统 TTS 评测不会测这几项，但对流式系统至关重要：

| 指标 | 计算方法 | 合格标准 |
| :--- | :--- | :--- |
| **流式↔离线一致性** | 同一测试句分别用「整句前向」和「逐块流式输入+流式输出」合成（评测期关闭 TF32），计算波形 RMS/Max 误差与 **MCD / F0 RMSE** | **数学等价实现下应接近 0**（FP32 隐状态最大误差 `< 1e-5`，端到端波形 RMS 误差 `< 1e-4`） |
| **切块接缝爆音率（Seam Click Rate）** | 在每个 chunk 拼接点前后 ±5 ms 窗口内，检测波形一阶差分异常尖峰（超过 `max(8σ_local, 10σ_global)`） | **0%**（严禁出现咔哒声） |
| **帧率调制电音比（`Mod_93Hz`）** | 对整流包络 `|wav|` 计算 `sr/hop`（`93.75 Hz`）处 DFT 幅值占 DC 比值（`a9` 新增，直接量化因果 iSTFT 帧率电音） | **`≤ 0.0035`**（实测健康 PreVocos ≈ `0.0023`，`a8` 电音期高达 `0.0081`） |
| **OLA 能量空洞数（`Energy_Holes`）** | 统计有声段内突发 `>12 dB`（帧 RMS `< 0.35×` 前后邻帧）的 1–3 帧相消塌陷次数（`a9` 新增，直接量化听感断层） | **接近 PreVocos 基线**（61 句合计 `≤ 12` 次，`a8` 曾高达 `35` 次） |
| **右前瞻收益曲线** | 同一主干固定测试集，对比 $L = 0$ vs $L = 4$ vs $L = 8$ 音素下的多音字准确率、三声变调与 NatScore/CMOS | 明确找到「延迟增加最小、听感跃升最大」的拐点 $L^*$ |
| **端侧开销指标** | 统一在固定 CPU 线程（如 2 核）测 **RTF**、**TTFA（首包音频延迟）**、**峰值内存（RSS）** | 目标 ARM 双核 `RTF < 0.10`，`TTFA < 150 ms` |

## 二、50 句黄金人工盲听集（最终拍板防骗机制）

**客观指标负责日常自动化筛选，但最后决定“哪个主干更好 / 能不能上线”一定要过人耳。**

建议在进入实验阶段前，先固化一份 **永不进入训练集的 50 句黄金听测集**（控制在 5–10 分钟可听完一轮）：

| 分组 | 句数 | 覆盖要点 |
| :--- | :--- | :--- |
| **1. 中文日常助手对话** | 12 句 | 问答、提醒、闲聊、疑问句与感叹句（检验是否像真人助手而非播音腔） |
| **2. 中文多音字与三声变调** | 10 句 | 「银行行长」「重复/重量」「你好/展览馆/买把好雨伞」等（**专门考验右前瞻能力**） |
| **3. 中文文本正则（TN）压力测试** | 6 句 | 年份 `2026年`、小数 `3.14%`、金额 `￥128.5`、电话/编号、时间 `14:30` |
| **4. 纯英文常用表达** | 8 句 | 语音助手高频英文短句、数字、连读与重音对比 |
| **5. 中英混读（Code-Switching）** | 10 句 | 科技/日常混读（如「帮我把 Wi-Fi 切换到 5G」「这个 API 的 latency 太高了」「明天上午有个 sync meeting」） |
| **6. 极端长度边界** | 4 句 | 2 句极短首包（3–5 字，如「好的，没问题」）+ 2 句超长句（60+ 字，测流式状态是否漂移） |

### 极简盲听打分法（CMOS，10 分钟完成一次主干对比）
* 把两个候选模型（例如 `SWA` vs `RWKV`，或 `L=0` vs `L=4`）对 50 句生成的音频随机打乱为 **A / B**（隐藏模型名）。
* 只需听完按 **5 档比较分（CMOS）** 记录：
  * `+2`：A 明显更像真人 / 明显更自然
  * `+1`：A 略好
  * `0`：听不出差别
  * `-1`：B 略好
  * `-2`：B 明显更好
* **同时勾选致命缺陷标签**（吞字 / 多音字错 / 机械嗡鸣 / 切块爆音 / 切英文串味）。只要某个方案出现零星**机械嗡鸣或吞字**，即使平均分高也一票否决或必须先修。

## 三、训练期防翻车监控节奏（控制时间与算力）

在严控数据量（15–25 小时）的单卡训练中，按如下节奏监控，避免白跑几万步才发现练歪：

1. **每 5k–10k steps（轻量自动抽检，耗时 < 2 分钟）**：
   - 固定合成 10 句代表性样本（中/英/混读/短句）存入日志；
   - 自动跑一次 `CER/WER + UTMOS + DNSMOS + Seam Click 检测`；
   - 人工花 1 分钟抽听 3–4 句，确认无对齐崩溃、无高频电流底噪。
2. **每个实验节点（如主干对比结束 / 对抗微调结束，耗时 ~15 分钟）**：
   - 跑完 **全量 50 句黄金集 + Seed-TTS-Eval 抽样子集（200 句）** 的四维客观指标；
   - 进行一轮 10 分钟 A/B 盲听 CMOS，记录进实验日志，决定下一步迭代。
